## 1. Purpose

The web version of Jolie's monthly **`Apex_Abstract Status Report_<date>.xlsx`** + the per-unit `UNIT <n> Abstract Status.pptx` decks she sends Apex. It answers one operational question: **which sections are behind on title work relative to their frac date?**

This is the **title-work counterpart** to Brad Ryan's leasing dashboard. Brad owns "how much of the unit is leased"; Jolie owns "is title done before the well fracs." They cover overlapping Apex units but Jolie's book is wider (units 59, 76, 89, 97, 105, 106 vs Brad's 59/76/105) and organized by **section**, not unit.

**Not** in scope: the Sectional Overview Reports (`Sectional Overview Report_<sec>_<parish>_<date>.xlsx` — a deeper, differently-structured per-section ownership study, mostly Sabine Parish, a separate workstream); non-Apex work; deedplots / acreage calcs (one-offs).

## 3. Navigation — two levels, matching the report

The report is `ALL SECTIONS` (index) → one tab per section. The dashboard mirrors that exactly.

### Level 1 — OVERVIEW (landing)

**Left: the section race table.** One row per section from the `ALL SECTIONS` tab, columns:

| Section | Apex Unit | Landman | Attorney | Status | Frac date | **Days to frac** | **Title complete** | Changes |
|---|---|---|---|---|---|---:|---:|:-:|

- `Status` — verbatim from the sheet: `WORKING` · `WORKING - HOLD PER TL` · `TITLE COMPLETE` (colour-coded).
- `Days to frac` — computed from `FRAC DATE`; negative = past due, rendered red.
- `Title complete` — % of the section's tracts at the "TO received" rung (from the section tab), as a mini bar.
- `Changes` — the sheet's own `CHANGES FROM LAST REPORT` (YES/NO) flag, plus a live diff badge when a prior workbook is configured.
- **Default sort: urgency** = a score combining frac proximity and outstanding title (`min(daysToFrac, 400)` ascending, then `title_complete` ascending). "Hold per TL" sections sort to the bottom of the active group. `TITLE COMPLETE` sections in a collapsed "done" group.
- Row click → Level 2 for that section.

**Right: the all-sections map.** Every section drawn as its section-boundary polygon (PLSS section grid clipped to each section, or the tract-layer extent hull), filled by **title-completion bucket**: `Title complete` (green) · `≥75%` (light green) · `25–75%` (amber) · `<25%` (grey) · `Hold per TL` (hatched). Section label = `S-TwpN-RngW` + unit. Click a section polygon → Level 2. Basemap + county context underneath.

### Level 2 — SECTION detail

Header strip: section, parish, Apex unit, **Abstractor** (RROG, LLC), **Title Attorney**, **Landman Instructions** (verbatim — these carry real meaning: "only 10+ acre tracts", "Base abstract up to subdivision then MORS", "Try to combine as much as possible"), spud date, frac date, days-to-frac, section status.

**Rung rollup** — the abstract→title ladder as horizontal bars (tracts + %), stages:

| Rung | Derived from the section-tab cell |
|---|---|
| Not started | tract row present, no Date Started / Submitted / TO |
| Working (abstract) | `WORKING - <abstractor>` in the Submitted-to-Atty column (carry the abstractor name/initials: M Owens, L Harter, D Kuperman, M Carpenter, …) |
| Abstract submitted | `<date> Abst #<n>` in the Submitted-to-Atty column (carry date + abstract #) |
| In review (attorney) | `IN REVIEW` (trailing status column) |
| **TO received** | `<date> File No. <n>` in the TO Received column (carry date + file #) — this is "done" |

Special tags surfaced but not counted as a rung: `Base abstract up to subdivision then MORS` (subdivision), `3rd Party - not assigned` (not Apex's — excluded from the % denominators), estimate dates (`est. 6/5/2026`).

**Per-tract table** — Tract · Tract Name · rung (as a status chip) · abstractor · abstract # + date · TO file # + date · notes. Searchable by tract, name, abstractor, abstract #.

**Section map** — the section's tracts coloured by rung (reuse the RROG dashboard's abstract-status map-layer machinery: `rrog.geometry` discover/load/join on tract #, one shared `L.canvas`, click a tract → detail card). Where a section has no clean tract geometry, embed the current `LA-<parish>_<sec>_ABS.pdf` as a panzoom image (same fallback pattern as the RROG build).

**Changes since last report** — when `CONFIGS` names a prior workbook: tracts that advanced a rung, new abstracts submitted, new TOs received, and any section that changed section-level status. Hidden when no prior is set.

## 6. The rung model (canonical)

```
not_started  →  working  →  abstract_submitted  →  in_review  →  to_received
```

`rung_of(cell_submitted, cell_to, cell_trailing) -> rung`:

1. `cell_to` matches `File No.` / `File #` → `to_received` (capture `to_date`, `to_file_no`).
2. else `cell_trailing` or `cell_submitted` contains `IN REVIEW` → `in_review`.
3. else `cell_submitted` matches `Abst #` → `abstract_submitted` (capture `abst_date`, `abst_no`).
4. else `cell_submitted` matches `WORKING` → `working` (capture `abstractor` = text after `WORKING -`).
5. else if the tract row has a `Date Started` → `working`.
6. else → `not_started`.

`3rd Party - not assigned` / `3rd Party` in the tract-name column → `tags += "3rd_party"`, excluded from % denominators. `Base abstract up to subdivision then MORS` → `tags += "subdivision"`. Section-level `STATUS == "TITLE COMPLETE"` overrides per-tract gaps only for the section badge, never for the per-tract table.

Colours (align to the RROG dashboard's abstract layer + the `LA-*_ABS.pdf` maps): `to_received` dark green · `in_review` teal · `abstract_submitted` light green · `working` amber · `not_started` grey · `3rd_party` hatched grey.

## 7. Build script — `build_abstract_dashboard.py`

Same shape as `build_rrog_dashboard.py`. Runs on the ArcGIS Pro Python. Steps:

1. Parse `Apex_Abstract Status Report_<date>.xlsx` → `AllSections` + per-section `SectionAbstract`.
2. Normalize section keys; join `ALL SECTIONS` rows to their section sheets.
3. Per section: resolve geometry (pinned shp → `discover_tract_layer` → `.gdb` TRACTS extract → PDF image), `join_tracts` on expanded tract id, compute rung rollup + `title_complete` %, coverage.
4. Build section-boundary polygons for the overview map.
5. `load_context_geojson` for parish outlines (Caddo / Bossier / DeSoto — `STATEFP == "22"`).
6. Prior-report diff if configured.
7. Embed logos, inline Leaflet, substitute into `abstract_template.html`, strip DEV_STUB, write `Apex_Abstract_Status.html` + a git-ignored `docs/abstract_build_report.md` (per-section geometry path/mode/coverage, rung tallies, days-to-frac table).
8. Print a summary: sections, tracts, per-section title-complete %, sections past frac, output size.

## 8. Success criteria

1. Every section sheet in the workbook renders a Level-2 view; the `ALL SECTIONS` rows all appear in the Level-1 table.
2. `days to frac` and `title complete %` computed correctly; past-due sections flagged red; sort defaults to urgency.
3. Rung classification matches the `LA-*_ABS.pdf` maps for every section rendered with live geometry.
4. The 5 shared sections reuse the RROG `data/` shapefiles with no re-hunt; the 4 new sections resolve to live geometry or a documented PDF-image fallback.
5. Composite/range tract keys (`3A&B`, `HH1-HH31`, `6-52`) expand for the map join and display grouped.
6. `3rd Party - not assigned` tracts are excluded from % denominators and visibly tagged.
7. Opens offline by double-click; no external requests except basemap tiles.
8. A section set that grows or shrinks next cycle needs no code change — the build enumerates sheet names.
9. `RROG_Dashboard.html` still builds and its test suite stays green (shared `rrog/` package only extended, never broken).

## 9. Known traps (carried from the RROG build + new)

1. Section-tab data starts at **column O**, not A — A–N are layout padding.
2. Section keys differ between `ALL SECTIONS` (`17N-12W-29`) and sheet names (`29-17N-12W`) — normalize.
3. Dates are ISO datetimes OR `M.D.YY` strings, sometimes with `est.` prefix.
4. Sec 1 / Sec 3 tract-ID coverage is partial (RROG known-issues); same badge applies.
5. `Apex_Abstract Status Report` filename date format is `M.D.YYYY` (`5.29.2026`), and copies land with ` (1)` suffixes — take the newest by mtime, or pin the path.
6. The section sheet count changes every cycle — never hard-code the 9.
7. Subdivisions collapse many lots into one tract row (`5 | Whippoorwill Subdivision`) OR span a range (`6-52`) — both occur in the same section.
8. `WORKING - <name>` carries the abstractor; `WORKING - HOLD PER TL` at the section level means the whole section is paused (title-lead hold), not an abstractor.
