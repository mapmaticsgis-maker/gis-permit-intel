## 1. Purpose

A single self-contained HTML page that lets Sabine read the Shelby North Area 1
leasing and title position at a glance. Left: tabbed analytics built from the two
weekly status workbooks. Right: interactive Leaflet map carrying the same content
as the two PDF status maps Doxa already sends.

This is a **much simpler position than Flatland North** — no bonus, no lease dates,
no expirations, no spend, no period ledger. What it has instead is a two-stage,
title-gated workflow, and the dashboard is organized around that rather than
around money.

### The workflow this dashboard models

Per the client:

> The title people are updating the ownership and report it based on the tract
> number from this map on their report. Once the ownership is verified, that's
> when the leasing agents know who to go and try to lease.

So the pipeline is:

```
tract universe (161, classified by AREA on the master map)
        ↓
title verification  (0-25% → 26-75% → 76-99% → 100%, or ON HOLD)
        ↓  handoff when ownership is verified
leasing pursuit     (Attempting to Contact → Contact Made → Negotiating
                     → Committed → Signed → Lease in Hand → LPR Complete)
```

Title is the gate. The single most useful view on the page is the **ready-to-lease
queue**: tracts whose title is done but where leasing has not started.

## 4. Workbook parsing

Both workbooks are visually formatted, not tabular. Structure is identical in both:

- Row 1 title, row 2 the status colour key, row 4 the column header, data from row 6.
- Columns: `A` STATUS · `B` TRACT NO. · `C` MINERAL OWNER · `D` ADDRESS ·
  `E` TRACT GMA'S · `F` MINERAL INTEREST · `G` LESSOR NMA'S ·
  `AF` TITLE COMMENTS · `AG` LEASE COMMENTS.
- Columns `H`–`O` and `W`–`AD` are a **visual scale bar**, not data. Their values are
  not reliably row-aligned to the tract block they describe (e.g. tract `163-002`'s
  bar value lands two rows above its block). **Do not parse them.** Column `A` is
  the authoritative status.
- A tract block starts on any row where `B` is non-empty; owner rows follow beneath
  with only `C`/`D` populated; blocks are separated by a blank row.

Both workbooks yield exactly 161 tract keys.

### 4.1 Composite key expansion — the one place tracts can be silently lost

11 workbook keys name several tracts at once, because title work and leasing are
assigned in packages:

```
'163-002 & 004,007,008,009'                  '520-001, 004, 005, 006, 008, 010 & 011'
'230-001 includes 230-002 & 230-003'         '520-002, 005, 007 & 009'
'230-002 (with 230-001)'                     '520-003 & 004, pt 005, 006, 008, 010, 011'
'230-003 (with 230-001)'                     '520-005 pt'
'459-006 also part of 459-003'               'Partial Tract Comprised of 520-001 & 002'
'459-015 & 018,034,038,051'
```

Expansion rule, in order:

1. If the key is already a `DOXA_TN` value, return it.
2. Find the **first full tract ID** anywhere in the string
   (`\d{3}(?:-\d{3})?-\d{3}`, which covers both `459-012` and the two-part
   `365-274-001`). Its leading portion establishes the *family* prefix.
3. Collect every bare 3-digit number in the string, prefix each with the family,
   keep those that exist in `DOXA_TN`, preserving order and de-duplicating.

Establishing the family from the first full ID rather than from the string's
leading characters is what makes `'Partial Tract Comprised of 520-001 & 002'`
resolve — that key does not begin with its family.

**This function gets a unit test** asserting all 11 strings above expand to the
expected tract lists and that the merged result covers 161/161 tracts. It is the
only place in the build where a parsing miss produces a plausible-looking but
wrong dashboard rather than a crash.

### 4.2 Merge

Per tract: geometry + `AREA` + `LSE_STAT` + `STATUS` from the shapefile;
lease status, owner roster, GMA, comments from #1; title bucket and runner
from #2. Where a composite key carries a status, it applies to every tract it
expands to.

Runner names arrive as `'Patrick Running'`, `'Luke running'`, `'Philip running'` —
strip the trailing `running` (case-insensitive) to get the person.

## 7. Prior-week snapshot handling

The prior-week workbooks were not available when this spec was written. Design
consequence: the build must not depend on them.

- Prior paths are two optional constants at the top of the build script.
- If either is unset or missing, the build logs `no prior snapshot — CHANGE tab
  hidden` and emits `null` for the change payload; the template hides the tab.
- When present, both are parsed by the **same** parser and expander as the current
  pair — no second code path — and diffed per tract on (lease status, title bucket,
  runner, presence).
- A tract present last week but absent this week is reported as `removed`, not
  silently dropped.

### Leaflet mechanics — carried over from the Flatland build

These are not optional; they are the fixes for bugs already paid for once:

- **One shared `L.canvas` renderer** across all hit-testable tract layers. Each
  `L.canvas` creates a full-map-sized `<canvas>` with `pointer-events:auto`, so only
  the topmost canvas receives clicks — per-layer canvases silently break selection.
- `L.svg` for any layer that must let clicks fall through (AOI outline, unit
  outlines) — SVG paths hit-test per path.
- Highlight overlays marked `interactive:false` + `pointer-events:none`.
- On tract select: **pan only if off-screen, never change zoom.** A
  `fitBounds({maxZoom:15})` zoom jump was the cause of the "map jams on select"
  stall in the Flatland build.
- `uid→feature` lookups via `Map`, not `Array.find()`. Canvas padding `0.15`.

At 161 tracts performance is not a concern; the hit-testing rules are about
correctness, not speed.

Runs on the ArcGIS Pro Python
(`C:\Program Files\ArcGIS\Pro\bin\Python\envs\arcgispro-py3\python.exe`), which has
`osgeo`, `pandas`, `openpyxl`, `PIL`. No new installs.

Note: the system Python 3.14 on this machine has a broken `openpyxl`/`numpy` import
chain and no GDAL — the ArcGIS Pro interpreter is required, not merely preferred.

Steps:

1. Parse both workbooks (§4) → `{key: record}`.
2. Expand composite keys (§4.1) → per-tract records. **Assert 161/161 coverage;
   fail loudly otherwise.**
3. Load `DOXA_TRACTS.shp`, merge attributes (§4.2), derive pipeline bucket per tract.
4. Load units, AOI, deep rights, abstracts (clipped), counties → reproject → GeoJSON.
5. Build the analytics payloads: pipeline buckets, funnel, title ladder, runner
   workload, area cross-tab, owner roster.
6. If prior-week paths are set, parse and diff (§7); else emit `null`.
7. Embed logos as data URIs, subset + embed Gotham woff2.
8. Substitute into `template.html`, write the output, report file size.
