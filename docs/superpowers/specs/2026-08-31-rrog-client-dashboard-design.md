## 1. Purpose

A single self-contained HTML page RROG can send its operator clients as a link in
place of emailing PowerPoint leasing decks and PDF status maps. For each unit it
shows RROG's abstract/title production status, the leasing funnel, and the
client's ownership/interest position, with an interactive map carrying the same
content as the lease-status and abstract-status PDF maps Mapmatics already
maintains for RROG.

This is a **multi-unit, multi-client** dashboard. v1 ships the **Apex** book of
three units. An **Aethon** group is added in a later cycle from the same code with
no structural change (Aethon master reports pending from RROG as of spec date).

### The workflow this models

RROG abstracts tracts and runs title, then Apex leases. Brad emails Mapmatics MOR
workbooks + lease-status PDFs/PPTX, then sends tract-by-tract color-change
requests (e.g. "change 22-25 to yellow", "17 from red to orange", "41-20 to
Blue", "to no color"); Mapmatics updates the ArcMap and returns fresh PDF + PPT.
The dashboard is the living web version of that loop.

Pipeline per unit:

```
tract universe (per unit OSR / survey tract list)
      │
abstract  (RROG abstract #: Working → In-Review → Complete)
      │
title     (title opinion ordered → received → certified)  ── RROG's deliverable
      │  handoff
leasing   (Unleased/no-contact → Working-letter-sent → Negotiating
           → Committed → Leased; or Holdout; or 3rd-party HBP; or State)
```

Because abstract/title is what RROG actually owes the operator, **the
Abstract & Title tab leads** (client direction).

## 5. Left panel — three tabs (per unit)

From `ABSTRACT STATUS` + `TO INVENTORY` (and, for N/2 later, its populated
inventory + `Production History`).

- **Status ladder**: tract packages by RROG abstract status
  (Working → In-Review → Complete), with tract count and acreage per rung and a

### Tab 2 — LEASING

- **Ready-to-lease queue**: tracts with a Complete abstract but still
  Unleased/no-contact or Working — the handoff view.
- Week-over-week deltas when a prior workbook is configured (see §7).
- For Unit 76, one funnel section per section (36 / 1 / 12) plus a cross-unit

## 6. Map

Layers bottom→top:

1. County / parish context, thin outline.
2. Section grid + labels for the unit's sections.
3. **Tract fill — mutually exclusive base layers**, radio-selected:
   *Lease status* (default, §4.2 colors) · *Abstract status*
   (Working / In-Review / Complete + not-started). Split-status → hatch.
4. Wells (spots + laterals), toggle.
5. Unit outline — bold; for Unit 76, the three section outlines.
6. Per-section: live GeoJSON where geometry was found, else the embedded PDF
   raster for that section.

Basemaps: **keyless only** — OSM / Esri World Imagery / Esri World Topo / None.
Never `basemaps.cartocdn.com`.

Filters ↔ map linked both ways. Click a tract → detail card: tract #, acreage,
lease status, abstract status, current owner(s), lessee, royalty, comments.

Leaflet mechanics carried verbatim from the Doxa/Flatland builds: one shared
`L.canvas` renderer across hit-testable tract layers; `L.svg` for outlines that
must pass clicks through; highlight overlays `interactive:false` +
`pointer-events:none`; on select **pan only if off-screen, never change zoom**;
`uid→feature` via `Map`; `fitBounds` deferred to `requestAnimationFrame` + `load`
with a home control.

## 7. Prior-report handling (Change view)

- Prior workbook path is an optional constant per unit at the top of the build.
- If unset/missing: build logs `no prior snapshot — <unit> CHANGE hidden`,
  emits `null`, template hides the delta rows for that unit.
- When present: parsed by the **same** parser; diffed per tract on
  (lease bucket, abstract status, presence). A tract present last cycle but
  absent this cycle is reported `removed`, not dropped.

## 8. Build script — `build_rrog_dashboard.py`

Lives in `C:\GIS\CLIENT\RROG\DASHBOARD\` beside `template.html` and `vendor/`.
Runs on the ArcGIS Pro Python
(`C:\Program Files\ArcGIS\Pro\bin\Python\envs\arcgispro-py3\python.exe`) —
`osgeo`, `pandas`, `openpyxl`, `PIL` present, no installs. System Python 3.14 is
unusable (broken `openpyxl`/`numpy`, no GDAL).

Structure: a `CONFIGS` table at the top listing clients → units → {workbook,
prior workbook, sections → {geometry candidates, PDF fallback}, report date}.
One function per source. `template.html` placeholder substitution at the end.

Steps:

1. For each unit: parse its workbook sheets (§4.1) → per-tract records +
   funnel totals + abstract/title packages + interest roll-ups.
2. Normalize funnel vocabulary (§4.2). Relabel Paloma → Apex (keep OGML
   lessee-of-record string, annotate).
3. Expand composite abstract/TO keys for per-tract join; keep the package
   grouping for display. Unit-test the expander on the known composite strings.
4. For each section: locate the authoritative tract layer; where found, load →
   reproject → simplify (~3 m) → round 6 dp → GeoJSON, join to workbook rows on
   tract ID, **assert coverage and log misses**; where not, rasterize the
   fallback PDF page to an embedded image and record the section as image-mode.
5. Load county + wells → reproject → clip → GeoJSON.
6. Prior-report diffs where configured, else `null`.
7. Embed logos (RROG, per-group client, Mapmatics) as data URIs.
8. Substitute into `template.html`, write output, report file size + the
   per-section geometry/image path table.

1. Client → Unit → tab navigation works; each Apex unit renders all three tabs +
   map from its workbook.
2. Funnel totals on the Leasing tab match the workbook's own PPT-numbers sheet
   (and the client's PPTX deck) to the acre.
3. Lease-status and abstract-status map layers classify identically to the
   current RROG PDF maps for every section rendered live.
4. Sections without clean geometry fall back to the PDF image without breaking
   the unit; the build report names which sections used which path.
5. Paloma appears nowhere as a current party — only as annotated
   lessee-of-record.
6. Abstract & Title tab renders correctly when the source inventory is empty
   (Unit 59 S/2) and shows the caveat.
7. Opens offline by double-click; no external requests except basemap tiles.
8. Adding the Aethon group later is a `CONFIGS` edit, not a template change.

## 11. Known data traps

1. "PALOMA" = Apex everywhere (lessee, "PALOMA LEASED ACREAGE", `COLOR=Y`).
2. Block-structured MOR sheets — group owner rows under the last-seen tract #.
3. Composite tract keys in abstract/TO sheets and OSR ("1, 1251A",
   "12 THROUGH 72", "984…988") — expand for join, display grouped.
4. Compound OSR tract IDs (`22-31`, `40-199`, `51-263`, `34.15`, `35.56`) are
   the map↔workbook join key; section shapefile tract-ID field varies and must
   be identified per section.
5. Funnel bucket spellings differ per workbook — normalize to §4.2.
6. Unit 76 spans 2 townships / 2 parishes / 3 section sheets + 2 cross-unit
   sheets; Unit % is per-section, cross-unit rollup is separate.
7. Unit 59 N/2 sheet schema is legacy ("Unit 7-MOR", "GPC UNIT #", "UNI 7"),
   1,816 rows, 2024 data — do not co-mingle with S/2 parsing.
8. `TO INVENTORY` empty for 59 S/2 (0 total), populated for N/2 (66 rows) —
   render gracefully either way.
9. `tl_2024_us_county` is national — `STATEFP == "22"` + parish name required.
10. Keyless basemaps only; `basemaps.cartocdn.com` returns placeholder tiles.
